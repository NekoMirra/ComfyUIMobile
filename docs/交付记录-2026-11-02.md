## 二、关键决策

### 2.1 Glasmio 选型依据

- Glasmio 0.1.1 的 core / glass / ui / preference / icons 五个模块，正好对应本项目需要的「主题令牌、液态玻璃材质、控件封装、图标解析」四类需求，core 与 glass 提供了 backdrop 采样与折射，ui 提供了与 iOS 观感接近的控件。
- 明确排除 `glasmio-scaffold`：它会拖入 Navigation3 与 MIUIX KMP，和本项目既有的 Compose Navigation 架构冲突。
- 图标不自带 SF Symbols 字体授权，改用 Glasmio 内置的 Material 图标解析器（`GlasmioIconProvider`），保证不引入字体资产依赖。

### 2.2 minSdk 26 → 33 的设备覆盖影响

- Glasmio 0.1.1 的 AAR 声明 `minSdkVersion=33`，因此最低版本只能抬到 Android 13（API 33）。
- 影响面：Android 12 及以下设备无法安装本轮候选版本。考虑到本项目是面向自建 ComfyUI 服务端的进阶工具、且需要 AGSL/RenderEffect 这类 Android 13 才稳定的能力，这个取舍是可接受的；但这是**破坏性兼容变更**，发布说明里必须写明，不能只当普通补丁发。
- 兜底：Android 13+ 的设备占当前活跃装机量的绝大多数，且升级路径由应用商店的最低版本约束强制，不需要应用内做降级提示。

### 2.3 compileSdk 37

- Glasmio 0.1.1 的 AAR 声明 `minCompileSdk=37`，用 36 编译会被 AGP 拒绝。
- 因此 `compileSdk = 37`，并在 `gradle.properties` 里加 `android.suppressUnsupportedCompileSdk=37`，避免每次构建都告警。`targetSdk` 仍保持 35，不改变运行时行为策略。

### 2.4 工具链升级链与各自原因

| 组件 | 升级前 | 升级后 | 原因 |
| --- | --- | --- | --- |
| Gradle | 8.11.1 | 9.7.1 | AGP 9.x 要求 Gradle 9.x |
| AGP | 8.10.1 | 9.4.1 | 需要 `android.newDsl` 与内建 Kotlin 支持，才能消费 Glasmio 的 AAR |
| Kotlin | 2.0.21 | 2.4.21 | Glasmio 0.1.1 的 AAR 带 Kotlin 2.4 元数据，只有 2.4 编译器能读 |
| Compose BOM | 2024.x 系（上游基线） | 2026.09.00 | Glasmio 0.1.1 对齐的基线（foundation 1.12.1 / material3 1.4.0 / ui 1.12.1） |
| jvmToolchain | 17 | 21 | AGP 9 + Kotlin 2.4 要求 JDK 21，同时与本机 OpenJDK 21.0.8 对齐 |
| JDK | 17 | 21.0.8 | 本机默认版本，满足 jvmToolchain(21) |
| compileSdk | 36 | 37 | Glasmio 0.1.1 AAR 声明 minCompileSdk=37 |
| minSdk | 26 | 33 | Glasmio 0.1.1 AAR 声明 minSdkVersion=33 |
| targetSdk | 35 | 35 | 未变，运行时行为策略不变 |

- AGP 9 移除了 `applicationVariants`，APK 改名改用 `androidComponents { onVariants(...) }` 的稳定 API。
- AGP 9 的内建 Kotlin 不兼容 `org.jetbrains.kotlin.android` 插件，因此 `gradle.properties` 里设置 `android.builtInKotlin=true`，只保留 `org.jetbrains.kotlin.plugin.compose`。

### 2.5 玻璃控件在无宿主时的降级

- Glasmio 的 `LocalGlassBackdrop` 在没有宿主时读取会直接抛异常。
- 独立窗口（`ComponentDialog` + `ComposeView`、独立 `ComposeView`）拿不到页面的 backdrop，因此新增 `LocalGlasmioHosted` 宿主标记：在 `GlasmioShell` 的 overlayContent 里置为 true，各个玻璃封装在标记为 false 时改用同一套 token 的 Material3 形态（配色、圆角、字号一致，不出现两套风格）。
- 生产路径不受影响：App 根壳始终是 `GlasmioShell`，页面内的玻璃控件仍走真实玻璃材质。

## 三、改动清单

### 3.1 服务器资产访问层

- `/api/assets` 的分页、缓存与合并策略落地：`ServerAssetCache`、`ServerAssetPagination`、`ServerGalleryMerge`。
- 服务器端未启用资源功能时，界面给出明确降级文案「服务器未启用资源功能，无法读取服务器图片」，而不是空白或崩溃。
- **访问前的能力门槛**（本轮收口）：访问「服务器图片 / 历史生成」之前先按 `GET /features` 的 `assets` 能力位判定，不再靠请求失败后才降级。
  - 判定依据：`ServerCapabilities.assetsEnabled`，随其它服务器能力在连接时一起读取并缓存（`ServerCapabilitiesClient.fetch` → `parseFeatures`，取 `optBoolean("assets", false)` 的宽松语义），**不额外发 `/features` 请求**，刷新节奏与既有 capabilities 一致（连接时探测 + 手动刷新按钮）。
  - 判定位置：新增纯逻辑 `network/ServerAssetSupport.assetsDisabledMessage(capabilities)`，落在 `MainViewModel.loadServerAssets` / `loadServerJobs`、`ui/ServerGalleryView.kt` 的「服务器图片 / 历史生成」两段、`ui/ServerAssetPickerSheet.kt` 三处。
  - 判定为「未启用」时界面直接给提示，**不发出注定失败的请求**；能力未知（还没探测到）时放行，仍由既有的 503 `SERVICE_DISABLED` → `ServerAssetsDisabledException` 兜底，不会把「没读到」误判成「没启用」。
  - 旧版服务器（没有 `/api/assets` 与 `/api/jobs`）落在同一类降级：没有 `/features` 时 `probeServerCapabilities` 回落成 `assetsEnabled = false`。
  - 降级文案在全部三处与异常兜底路径上统一为原文「服务器未启用资源功能，无法读取服务器图片」。

### 3.5 节点图

- `NodeGraphView`：以画布形式呈现工作流节点图，支持缩放、徽标与选中态。
- **执行中节点的可见区分与进度条**（本轮核对结论）：两半都在，链路完整。
  - 可见区分：`ui/NodeGraphView.kt` 的 Canvas 内 `if (executing)` 分支画 4f 粗描边，颜色取 `NodeGraphColors.executingBorder`（Glasmio success token）；选中节点另画 `selectedBorder`（glass.accent）3f 描边，两者可叠加区分。
  - 进度条：同一 `if (executing)` 分支在节点下方（`barTop = top + height + 4f`）画 `PROGRESS_BAR_HEIGHT = 5f` 高的进度条。**确定态**：`nodeProgress[node.id] != null` 时按 `progress.coerceIn(0f, 1f)` 的比例填充 `progressFill`；**不确定态**：没有进度值时画 30% 宽的滑动段，位移由 `indeterminatePhase` 驱动，而 `rememberInfiniteTransition` 只在 `needsIndeterminate`（存在执行中且缺进度值的节点）时才启动，空闲时不空转帧时钟。
  - 进度值的接线：`network/ProgressStateParser.parse` 解析 websocket 的 `progress_state` → `MainViewModel.handleSocketMessage` 的 `"progress_state"` 分支 → `showVisibleExecutingNode(promptId, nodeId, progress)` → `AppUiState.executingNodeIds` / `AppUiState.nodeProgress` → `ui/ComfyMobileApp.kt` 的 `NodeGraphView` 调用点 → 画布。另一条 `"progress"` 分支只更新任务级 `generationProgress`，不进图，这是对的。
  - 点击定位参数卡片：`NodeGraphView` 的 `detectTapGestures` 做画布坐标命中检测（除以 scale + offset 还原图坐标）→ `onSelectNode(hit.node.id)` → `ui/ComfyMobileApp.kt` 里 `viewModel.selectNode(nodeId)`（写 `state.selectedNodeId`，图上画选中描边）+ 展开该节点卡片 + 延迟 80ms 后 `nodeRequesters[nodeId]?.bringIntoView()` 把该节点的 `NodeParameterCard` 滚进可视区。
- **本轮修掉的真实缺陷**：原实现用 `executingNodeIds = ui.executingNodeIds + resolvedNodeId` 只增不减，上一个节点结束后永远不会熄灯，图上会留下一串永远亮着、进度条冻在最后一帧的旧节点，与参数页 `currentExecutingNodeId` 的单一高亮也对不上。改为同一时刻只保留当前执行节点（新增纯数据类 `network/VisibleExecution` + 成员函数 `executing(nodeId, progress)`），并在失败、取消、清队列、本地保存完成四条收尾路径与 `TaskLifecycle.settle` 一并清空高亮与进度。

### 3.6 节点模式

- `NodeModePolicy`（前端桥接语义）与 `NodeModeState`（App 侧状态）区分「始终执行 / 静音 / 绕过」三种模式：
  - mode 0 = 始终执行，节点正常进入 api prompt。
  - mode 2 = 静音，节点不进入 api prompt，下游拿不到它的输出。
  - mode 4 = 绕过，节点不进入 api prompt，下游改接该节点的上游输出。
- 工作流序列化会带出 `nodes[].mode`，作为 App 侧工作副本的同步依据。

## 五、已知限制

1. **Android 12 及以下设备不再支持**：minSdk 从 26 抬到 33 是 Glasmio 0.1.1 AAR 的硬性要求，属于破坏性兼容变更。
2. **与上游官方包签名不同，不能互相覆盖安装**：上游的发布私钥不在本 fork 内（也从未被访问），本 fork 使用**自建签名密钥**（keystore 在 `.local/android/signing/`，被 `.gitignore` 覆盖、不进版本库）。因此 `:app:assembleRelease` 能正常产出并通过验签的**签名 release 包**（0.2.0-fork.1 与 0.2.1-fork.1 均已发布）。但本 fork 的签名与上游官方包不同（包名同为 `com.local.comfyuimobile`），Android 判定为不同签名来源，**两者无法互相覆盖安装**：从上游官方版升级需先卸载上游包再安装本 fork 版，卸载会清除本地数据，请先备份作品与草稿；从本 fork 的旧版本（如 0.2.0-fork.1）升级则可直接覆盖安装，数据保留。

4. **Robolectric 需要 4g 测试堆 + 分片**：全量一次跑曾有 5 个用例因内存不足失败，现在按包分片跑（7 片，每片单独一个 JVM），并把 `it.maxHeapSize` 提到 4g。
5. **本机没有运行中的 ComfyUI**：节点 mode 的真实前端核验本轮无法重跑，结论沿用 2026-11-02 的日志。
6. **真机未验证项**：真实玻璃材质的折射/模糊效果、AGSL RuntimeShader 在不同厂商 ROM 上的表现、窄屏头部两行布局在真机上的手感、独立窗口（`ComponentDialog` + `ComposeView`）里的 Material3 降级形态观感，都还需要真机走查。
