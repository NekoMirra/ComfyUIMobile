## 二、关键决策

### 2.1 Glasmio 选型依据

- Glasmio 0.1.1 的 core / glass / ui / preference / icons 五个模块，正好对应本项目需要的「主题令牌、液态玻璃材质、控件封装、图标解析」四类需求，core 与 glass 提供了 backdrop 采样与折射，ui 提供了与 iOS 观感接近的控件。
- 明确排除 `glasmio-scaffold`：它会拖入 Navigation3 与 MIUIX KMP，和本项目既有的 Compose Navigation 架构冲突。
- 图标不自带 SF Symbols 字体授权，改用 Glasmio 内置的 Material 图标解析器（`GlasmioIconProvider`），保证不引入字体资产依赖。

### 2.2 minSdk 26 → 33 的设备覆盖影响

- Glasmio 0.1.1 的 AAR 声明 `minSdkVersion=33`，因此最低版本只能抬到 Android 13（API 33）。
- 影响面：Android 12 及以下设备无法安装本轮候选版本。考虑到本项目是面向自建 ComfyUI 服务端的进阶工具、且需要 AGSL/RenderEffect 这类 Android 13 才稳定的能力，这个取舍是可接受的；但这是**破坏性兼容变更**，发布说明里必须写明，不能只当普通补丁发。
- 兜底：Android 13+ 的设备占当前活跃装机量的绝大多数，且升级路径由应用商店的最低版本约束强制，不需要应用内做降级提示。

### 2.3 compileSdk 37

- Glasmio 0.1.1 的 AAR 声明 `minCompileSdk=37`，用 36 编译会被 AGP 拒绝。
- 因此 `compileSdk = 37`，并在 `gradle.properties` 里加 `android.suppressUnsupportedCompileSdk=37`，避免每次构建都告警。`targetSdk` 仍保持 35，不改变运行时行为策略。

### 2.4 工具链升级链与各自原因

| 组件 | 升级前 | 升级后 | 原因 |
| --- | --- | --- | --- |
| Gradle | 8.11.1 | 9.7.1 | AGP 9.x 要求 Gradle 9.x |
| AGP | 8.10.1 | 9.4.1 | 需要 `android.newDsl` 与内建 Kotlin 支持，才能消费 Glasmio 的 AAR |
| Kotlin | 2.0.21 | 2.4.21 | Glasmio 0.1.1 的 AAR 带 Kotlin 2.4 元数据，只有 2.4 编译器能读 |
| Compose BOM | 2024.x 系（上游基线） | 2026.09.00 | Glasmio 0.1.1 对齐的基线（foundation 1.12.1 / material3 1.4.0 / ui 1.12.1） |
| jvmToolchain | 17 | 21 | AGP 9 + Kotlin 2.4 要求 JDK 21，同时与本机 OpenJDK 21.0.8 对齐 |
| JDK | 17 | 21.0.8 | 本机默认版本，满足 jvmToolchain(21) |
| compileSdk | 36 | 37 | Glasmio 0.1.1 AAR 声明 minCompileSdk=37 |
| minSdk | 26 | 33 | Glasmio 0.1.1 AAR 声明 minSdkVersion=33 |
| targetSdk | 35 | 35 | 未变，运行时行为策略不变 |

- AGP 9 移除了 `applicationVariants`，APK 改名改用 `androidComponents { onVariants(...) }` 的稳定 API。
- AGP 9 的内建 Kotlin 不兼容 `org.jetbrains.kotlin.android` 插件，因此 `gradle.properties` 里设置 `android.builtInKotlin=true`，只保留 `org.jetbrains.kotlin.plugin.compose`。

### 2.5 玻璃控件在无宿主时的降级

- Glasmio 的 `LocalGlassBackdrop` 在没有宿主时读取会直接抛异常。
- 独立窗口（`ComponentDialog` + `ComposeView`、独立 `ComposeView`）拿不到页面的 backdrop，因此新增 `LocalGlasmioHosted` 宿主标记：在 `GlasmioShell` 的 overlayContent 里置为 true，各个玻璃封装在标记为 false 时改用同一套 token 的 Material3 形态（配色、圆角、字号一致，不出现两套风格）。
- 生产路径不受影响：App 根壳始终是 `GlasmioShell`，页面内的玻璃控件仍走真实玻璃材质。

## 三、改动清单

### 3.1 服务器资产访问层

- `/api/assets` 的分页、缓存与合并策略落地：`ServerAssetCache`、`ServerAssetPagination`、`ServerGalleryMerge`。
- 服务器端未启用资源功能时，界面给出明确降级文案「服务器未启用资源功能，无法读取服务器图片」，而不是空白或崩溃。

### 3.2 作品管理

- 作品（媒体结果）列表、相册分组、收藏与保存入口接通；作品卡片的稳定 key 保证列表增量刷新不错位。

### 3.3 选图

- 服务器图片选择器 `ServerAssetPickerSheet`：分页浏览、缩略图加载、插入工作流参数。

### 3.4 提示词库

- `PromptLibraryStore` / `PromptLibrarySelection`：提示词库的本地存储、检索与选择，入口在参数编辑面板与工具栏。

### 3.5 节点图

- `NodeGraphView`：以画布形式呈现工作流节点图，支持缩放、徽标与选中态。

### 3.6 节点模式

- `NodeModePolicy`（前端桥接语义）与 `NodeModeState`（App 侧状态）区分「始终执行 / 静音 / 绕过」三种模式：
  - mode 0 = 始终执行，节点正常进入 api prompt。
  - mode 2 = 静音，节点不进入 api prompt，下游拿不到它的输出。
  - mode 4 = 绕过，节点不进入 api prompt，下游改接该节点的上游输出。
- 工作流序列化会带出 `nodes[].mode`，作为 App 侧工作副本的同步依据。

### 3.7 节点面板脚本

- 节点面板脚本注入与回调守卫：未变更时不回调，变更时按新值回调。

### 3.8 服务器能力与诊断

- 服务器能力清单、连接诊断、缓存规则、原始文件下载、任务接管等能力接通到界面。

- 节点图的不确定态进度条原本无条件启动无限动画（`rememberInfiniteTransition`），改为「只有执行中且没有进度值的节点才启动」，否则测试帧时钟无法进入空闲。

## 五、已知限制

1. **Android 12 及以下设备不再支持**：minSdk 从 26 抬到 33 是 Glasmio 0.1.1 AAR 的硬性要求，属于破坏性兼容变更。
2. **release 签名包出不来**：缺少发布签名私钥，`:app:assembleRelease` 会被 `gradle.taskGraph.whenReady` 的守卫直接拦下，本轮只产出 debug 包。
3. **Robolectric 下无法渲染真实玻璃**：Glasmio 的 backdrop 采样在 Robolectric 里持续产生帧，帧时钟永远不 idle，测试会挂住。因此 UI 测试统一走「无宿主降级形态」，覆盖的是自适应布局与设置项行为，不覆盖玻璃渲染本身；玻璃材质的真机表现仍需真机验证。
4. **Robolectric 需要 4g 测试堆 + 分片**：全量一次跑曾有 5 个用例因内存不足失败，现在按包分片跑（7 片，每片单独一个 JVM），并把 `it.maxHeapSize` 提到 4g。
5. **本机没有运行中的 ComfyUI**：节点 mode 的真实前端核验本轮无法重跑，结论沿用 2026-11-02 的日志。
6. **真机未验证项**：真实玻璃材质的折射/模糊效果、AGSL RuntimeShader 在不同厂商 ROM 上的表现、窄屏头部两行布局在真机上的手感、独立窗口（`ComponentDialog` + `ComposeView`）里的 Material3 降级形态观感，都还需要真机走查。
7. **换肤后仍保留的 Material3 形态**：独立窗口内的对话框与底部弹层，以及 `MaterialTheme.typography` 作为文字排版入口，都不是遗漏，而是玻璃材质在独立窗口里拿不到 backdrop 的物理限制。
